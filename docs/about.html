How the pipeline works

← Studio board

Stages

building an agent is on it · review built, waiting for a second look · queued waiting for a builder · planning waiting for a design pass · live nothing in flight · shelf parked.

Verdicts

ship ready to show people · revise worth more work · shelf parked. “Needs you” marks a game only when it has no queued or running work and either a question is waiting for a human answer or a new version is live to play (automatic rule: priority P1 or P2 only). Those games are the first view and are grouped by why. “Ready to try” lists live games with no queued work that changed since your last verdict.

Queue estimate

Each unfinished task uses its planned minutes from the intake. Work is divided across the active Codex job lanes and the Claude worker; the later worker finish is the queue finish estimate.

Cost

API dollars are metered. Codex and in-session Claude runs are on flat plans, so their totals are estimated from list token price or comparable metered runs. Earlier rounds are estimated the same way. Details are on Stats.

How updates reach this board

An agent claims a task by moving its file into a queue folder and committing to that task’s branch: first start: …, then work-in-progress commits. Every two minutes, a script reads the queue folders, branch commits, the change log, and the cost ledger. It writes the board data and pushes it only when something changed. GitHub Pages usually serves that update within about a minute, and this page checks again every 90 seconds.

Data

The board reads data/status.json, rebuilt when a task moves or an agent commits and checked again every 90 seconds.
